# Design: In-App Email Service (ComplyTrack Mail)

Generated by office-hours on 2026-08-11
Status: DRAFT
Mode: Builder

## Problem Statement

ComplyTrack users need to send and receive emails directly from the app without switching to Gmail/Outlook. This is an internal tool for your existing users — a full email client (SMTP send + IMAP receive) built into the dashboard, with attachment support and usage reporting.

## What Makes This Cool

A Gmail-like experience inside ComplyTrack: compose with rich text, drag-and-drop attachments, inbox/sent/drafts/trash folders, real-time sync, and email analytics — all without leaving the app.

## Premises

1. Users authenticate via ComplyTrack (JWT) and email credentials are stored per-organization
2. SMTP for sending, IMAP for receiving — standard provider support (Gmail, Outlook, etc.)
3. Emails are cached in MongoDB for fast UI rendering and search
4. Attachments stored in `server/email-attachments/` (gitignored, Docker volume)
5. IMAP polling every 30s for new mail (not WebSocket push — keeps it simple)
6. All email features behind auth middleware

## Architecture

### Backend (Express + MongoDB)

**New files to create:**

1. **`server/src/models/EmailConfig.js`** — Per-org SMTP/IMAP settings
   - Fields: organization, smtpHost, smtpPort, smtpUser, smtpPass (encrypted), imapHost, imapPort, imapUser, imapPass (encrypted), isActive, lastSyncAt

2. **`server/src/models/Email.js`** — Cached email messages
   - Fields: organization, messageId (IMAP UID), folder (inbox/sent/drafts/trash), from, to, cc, bcc, subject, textBody, htmlBody, attachments[], isRead, isStarred, labels[], receivedAt, sentAt, createdAt

3. **`server/src/models/EmailAttachment.js`** — Attachment metadata
   - Fields: email (ref), filename, originalName, mimeType, size, path, createdAt

4. **`server/src/services/emailService.js`** — Core email logic
   - `sendEmail(orgId, { to, cc, bcc, subject, html, text, attachments })` — SMTP send via nodemailer
   - `fetchInbox(orgId)` — IMAP fetch new messages, save to MongoDB
   - `syncFolder(orgId, folder)` — Sync specific IMAP folder
   - `getAttachment(emailId, attachmentId)` — Stream attachment file

5. **`server/src/controllers/emailController.js`** — API handlers
   - `POST /api/email/send` — Send email with attachments
   - `GET /api/email/messages?folder=inbox&page=1&limit=20` — List messages
   - `GET /api/email/messages/:id` — Get single message
   - `PATCH /api/email/messages/:id/read` — Toggle read status
   - `PATCH /api/email/messages/:id/star` — Toggle star
   - `DELETE /api/email/messages/:id` — Move to trash
   - `POST /api/email/drafts` — Save draft
   - `GET /api/email/drafts/:id` — Get draft
   - `DELETE /api/email/drafts/:id` — Delete draft
   - `POST /api/email/sync` — Trigger manual IMAP sync
   - `GET /api/email/config` — Get org email config
   - `POST /api/email/config` — Save org email config
   - `GET /api/email/attachments/:id/:attachmentId` — Download attachment
   - `GET /api/email/stats` — Email usage stats (sent count, received count, by day)

6. **`server/src/routes/email.js`** — Route definitions

7. **`server/src/middleware/emailAuth.js`** — Verify email config exists for org
